# Wiki Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The wiki module itself — publicly-readable pages with a BlockNote editor, a reorganizable tree, permanent slugs, full revision history with restore, optimistic-lock conflict handling, Postgres full-text search, and flat comments.

**Architecture:** New tables (`wiki_page`, `wiki_page_revision`, `wiki_page_comment`) and a service layer split by concern (`page-service.ts`, `revision-service.ts`, `comment-service.ts`, `search.ts`), matching the existing `events` module's split (`details-service.ts`, `signup-service.ts`, ...). Images reuse the `ImageStorage` interface built in the task-entity plan (`src/lib/images/`) rather than rebuilding it. Writing requires the `wiki-editor` role and its request flow, both built in the role-requests plan — this plan only *consumes* `requestRoleAction` and `hasAnyRole`, it doesn't touch the roles module.

**Tech Stack:** Next.js 16 App Router, Drizzle ORM, Postgres (PGlite in tests), vitest, BlockNote (`@blocknote/core`, `@blocknote/react`, `@blocknote/shadcn` — new dependencies).

**Spec:** `docs/superpowers/specs/2026-11-02-wiki-design.md` (all sections except §3's `task` table, which belongs to the task-entity plan).

**Depends on:** `2026-11-02-role-requests.md` (the `wiki-editor` role, `requestRoleAction`) and `2026-11-02-task-entity.md` (`src/lib/images/` — `ImageStorage`, `getImageStorage`, `prepareImageUpload`). Both must be implemented first.

## Global Constraints

- Every page is publicly readable — no `requireUser()` on any read path (spec §2). Every write path requires `hasAnyRole(actor, ['admin', 'wiki-editor'])`.
- A page's `slug` is generated once (via `slugify` + a uniqueness suffix, mirroring `projects/service.ts`'s `uniqueSlug`) and never changes, even when the title changes (spec §5).
- `parentId`/`position` (the tree) are fully independent of `slug` (the URL) — moving or reparenting a page never touches its slug.
- Every save (`updatePage`) writes a full-content `wiki_page_revision` snapshot in the same transaction — never a diff (spec §3).
- Optimistic locking: `wiki_page.version` increments on every save; a save whose `expectedVersion` doesn't match the current value is rejected, no merge attempted (spec §6).
- Deletion is a status flip (`'published'` → `'deleted'`), never a hard delete, and is blocked while the page still has non-deleted children (spec §3).
- Search is plain Postgres full-text (`to_tsvector`/`plainto_tsquery`), computed at query time from a plain `search_text` column kept in sync on save — no DB-generated column, no `pg_trgm` (spec §6, refined below).
- Comments are a flat list, no threading, no history (spec §7).
- Image uploads go through `getImageStorage()`/`prepareImageUpload()` from `src/lib/images/` (task-entity plan) — this plan adds no second storage implementation.

**Refinement from the spec**: §4/§6 originally described a DB `GENERATED ALWAYS AS` column computed from application code, which Postgres cannot do (a generated column can only use IMMUTABLE SQL expressions, not call out to JS). This plan instead: (a) stores a plain `search_text` column, written by the service on every save via `extractPlainText(content)`, and (b) creates a GIN index on the SQL expression `to_tsvector('english', coalesce(title,'') || ' ' || coalesce(search_text,''))` directly in the migration (hand-added after `drizzle-kit generate`, since expression indexes aren't something `schema.ts` can declare) — search queries compute `to_tsvector` at query time against that index, rather than reading a precomputed column. Simpler, and avoids depending on a Drizzle API that may not exist for generated `tsvector` columns.

## Review Focus

- Saving a page whose `version` has moved on (someone else saved first) must reject with a distinguishable error, not silently overwrite — the single most important behavior in this plan.
- Deleting a page that still has published children must be blocked, not silently orphan them or cascade-delete them.
- `getPageBySlug` and `getPageTree` must never return a `'deleted'` page — a direct slug hit on a deleted page is a 404, not a resurrection.
- A comment delete attempted by someone who is neither the author nor an admin/wiki-editor must be rejected.
- A search query containing characters `plainto_tsquery` could choke on (quotes, `&`, `|`, `!`) must not throw — `plainto_tsquery` already sanitizes its input defensively, but this needs an explicit test, not an assumption.

**Interfaces:**

- [ ] **Step 1: Add the three tables** to `src/db/schema.ts`, using the exact shape from spec §3 (as corrected above — `content: jsonb`, plus a new `searchText: text('search_text').notNull().default('')` column on `wikiPage`, no generated column):

```ts
export type WikiPageStatus = 'published' | 'deleted';

export const wikiPage = pgTable('wiki_page', {
  id: text('id').primaryKey(),
  slug: text('slug').notNull().unique(),
  title: text('title').notNull(),
  content: jsonb('content').notNull(),
  searchText: text('search_text').notNull().default(''),
  parentId: text('parent_id').references((): AnyPgColumn => wikiPage.id),
  position: integer('position').notNull().default(0),
  status: text('status', { enum: ['published', 'deleted'] }).$type<WikiPageStatus>().notNull().default('published'),
  version: integer('version').notNull().default(1),
  createdByUserId: text('created_by_user_id').notNull().references(() => user.id),
  createdAt: timestamp('created_at').notNull().defaultNow(),
  updatedAt: timestamp('updated_at').notNull().defaultNow(),
});

export const wikiPageRevision = pgTable('wiki_page_revision', {
  id: text('id').primaryKey(),
  pageId: text('page_id').notNull().references(() => wikiPage.id, { onDelete: 'cascade' }),
  title: text('title').notNull(),
  content: jsonb('content').notNull(),
  editedByUserId: text('edited_by_user_id').notNull().references(() => user.id),
  createdAt: timestamp('created_at').notNull().defaultNow(),
});

export const wikiPageComment = pgTable('wiki_page_comment', {
  id: text('id').primaryKey(),
  pageId: text('page_id').notNull().references(() => wikiPage.id, { onDelete: 'cascade' }),
  authorUserId: text('author_user_id').notNull().references(() => user.id),
  body: text('body').notNull(),
  createdAt: timestamp('created_at').notNull().defaultNow(),
});

export type WikiPage = typeof wikiPage.$inferSelect;
export type WikiPageRevision = typeof wikiPageRevision.$inferSelect;
export type WikiPageComment = typeof wikiPageComment.$inferSelect;
```

The self-referencing `parentId` needs the `AnyPgColumn` return-type annotation Drizzle requires for self-references — check `area`/other self-referencing tables in this file for the exact existing pattern, if one exists, and match it; otherwise use `text('parent_id').references((): AnyPgColumn => wikiPage.id)` as above.
